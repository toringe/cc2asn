**Goal:** Customers can buy Pro ($10/month or $100/year) through Stripe, get an API key from a one-time claim page, and make up to 1,000 historic lookups a day. Access ends on its own when the subscription does.

**Architecture:** All changes are in the existing stdlib HTTP app in `api/`. Stripe is called with stdlib HTTPS from `lib/billing.py` only: once when a checkout is claimed, and at most once per key per UTC day to check the subscription. No webhooks. Keys and claim markers live in the existing `cc2asn-tokens` DynamoDB table. HTML pages are Python string constants in `lib/pages.py`, so the Makefile's zip (`server.py run.sh lib`) needs no change.

**Tech Stack:** Python 3.14 stdlib (`http.server`, `urllib.request`, `unittest`), boto3 DynamoDB resource API, Stripe REST API v1 with a restricted key.

**Spec:** `docs/superpowers/specs/2026-11-09-pro-tier-design.md`

## Global Constraints

- Run every command from `api/`. Run tests with `uv run --with boto3 python -m unittest discover -s test -t .`. The repo `.venv` does not exist in this checkout; Task 1 creates it, after which the plain `uv run python -m unittest discover -s test -t .` works too.
- Pro is the only paid tier. Historic lookups require `item["tier"] == "pro"`.
- Default daily quota is **1,000** historic lookups.
- Key format: `cc2asn_pro_` + `secrets.token_hex(16)`. Store only `hash_token(key)` (SHA-256 hex). Show the plaintext once.
- Allowed subscription statuses: `active`, `trialing`, `past_due`. Every other status, or a missing subscription, means deny.
- Stripe-outage grace: allow for up to **72 hours** after the last successful check.
- Burst limit: **300 requests/minute per key, per warm environment**, enforced with `RateLimiter`.
- "Today" means the **UTC** date everywhere in the server. Today it uses `date.today()`, which is wrong outside UTC.
- New env vars: `CC2ASN_STRIPE_KEY` (restricted key: read Checkout Sessions and Subscriptions), `CC2ASN_STRIPE_PRODUCT` (`prod_…`), `CC2ASN_PRO_LINK_MONTHLY`, `CC2ASN_PRO_LINK_ANNUAL`. If the key is empty, billing is disabled. If a link is empty, `/pro` shows "not yet available" instead of a buy button. That is how links stay unpublished after deploy.
- No Stripe SDK. Add no new dependencies.
- Leave unchanged: anonymous latest-day lookups, `_client_ip()` with bridge/proxy trust, and both query log line formats.
- Claim responses carry `Cache-Control: no-store` and `Referrer-Policy: no-referrer`.
- `update-function-configuration --environment` replaces **all** variables, so always pass the full set.
- Deviation from the spec's field name: the spec's `last_ok_on` is stored as **`last_ok_at`**, a full UTC timestamp (`YYYY-MM-DDTHH:MM:SSZ`). A date alone cannot measure 72 hours.

## Review Focus

1. **Day boundary.** A key that used its full quota yesterday gets the full quota at 00:00 UTC, not at local midnight. A request that crosses midnight must not be charged against the wrong day. Covered by Task 2 `test_new_day_resets_after_exhausted_yesterday` and Task 3 `test_today_is_utc`.
2. **Customer reloads the claim page or opens it in two tabs at once.** Exactly one key is ever issued. The other view says "already claimed" with a contact address, and no orphan key stays usable. Covered by Task 6 `test_concurrent_claim_issues_one_key` and `test_reload_shows_already_claimed`.
3. **Stripe is slow or down during a lookup.** A paying customer keeps working, and each request does not wait out a timeout. Covered by Task 4 `test_outage_backoff_skips_stripe_for_60s` and `test_outage_within_72h_allows`.
4. **A cancelled customer keeps a cached-looking key.** Once Stripe reports `canceled`, every request that day is denied, not just the first. Covered by Task 4 `test_denied_today_is_remembered_without_stripe_call`.
5. **The old `standard` token, and manual pro tokens with no subscription.** `standard` gets 403, not 500. A manual pro token never calls Stripe. Covered by Task 3 `test_standard_tier_gets_403` and Task 4 `test_manual_token_skips_stripe`.

  - Module-level `utcnow()` in `server.py` that returns `datetime.now(timezone.utc)`. The server derives `today` from it, and tests patch it.

Historic branch order, which is the decision here:
1. Authorize, else 401.
2. Tier must be `pro`, else **403** `Pro tier required. See /pro\n`.
3. Key burst limit (keyed on `item["tk"]`), else 429 with `Retry-After: 60`.
4. `remaining() <= 0` gives 429 `Token quota exhausted\n` with `Retry-After: <seconds to midnight>`.
5. Gate check (Task 5), else 401.
6. Fetch from S3. On 404, return without charging.
7. `consume()`. On `None`, 429 as in step 4.
8. Log, then 200 with `X-Quota-Limit` and `X-Quota-Remaining` (`limit - used`).

`Throttled` raised anywhere in steps 1–7 gives **429** `Busy, retry shortly\n` with `Retry-After: 1`.

  - `class StripeClient(api_key: str, timeout: float = 3.0, opener=None)`. `opener(req: urllib.request.Request, timeout: float) -> tuple[int, bytes]` defaults to a `urllib.request.urlopen` wrapper that also returns `HTTPError` status and body.
    - `get_checkout_session(session_id: str) -> dict | None`: `GET https://api.stripe.com/v1/checkout/sessions/{id}?expand[]=line_items`. `None` on 404.
    - `get_subscription(sub_id: str) -> dict | None`: `GET /v1/subscriptions/{id}`. `None` on 404.
    - Header `Authorization: Bearer <key>`. URL-quote the ids.
  - `claimable_subscription(session: dict, product_id: str) -> str | None`: returns `session["subscription"]` only when `mode == "subscription"`, `status == "complete"`, `payment_status == "paid"`, the subscription is a non-empty string, and some `line_items.data[].price.product == product_id`.
  - `class SubscriptionGate(client: StripeClient, tokens: TokenStore, clock=time.monotonic)`, with `allows(item: dict, now: datetime) -> bool`:

```
sub = item.get("stripe_subscription");  no sub            -> True  (manual token)
today = now.date().isoformat()
item["checked_on"] == today      -> return item.get("last_ok_at", "").startswith(today)
within outage backoff (clock)    -> return in_grace(item, now)
try get_subscription(sub)  except BillingError: start backoff; log warning; return in_grace(item, now)
ok = sub is not None and sub["status"] in ALLOWED_STATUSES
tokens.record_check(item["tk"], today, iso_z(now) if ok else None)   # best-effort: log and ignore any exception
return ok
in_grace: parse last_ok_at; missing or unparseable -> False; now - last_ok_at <= GRACE
```

Known consequence: a key denied today stays denied until 00:00 UTC, even if the customer fixes payment. `past_due` is allowed, so a failed renewal does not trigger this. Record that in the docstring.

### Task 6: `GET /billing/claim`: issue a key once per checkout session

**Files:**
- Modify: `api/lib/tokens.py` (add `create_claimed`)
- Modify: `api/lib/billing.py` (add `ClaimService`)
- Create: `api/lib/pages.py` (claim page HTML)

- Test: `api/test/test_tokens.py`, `api/test/test_billing.py`, `api/test/test_server.py`

**Interfaces:**
- Produces:
  - `TokenStore.create_claimed(session_id: str, subscription: str, customer: str, now: datetime) -> str | None`. It generates a key, puts the token item (`tk`, `name="stripe:<customer>"`, `tier="pro"`, `daily_quota=1000`, `stripe_subscription`, `claim_session`, `checked_on=today`, `last_ok_at=iso_z(now)`), then makes a conditional put of `{"tk": "claim#<session_id>", "token_tk": <hash>, "claimed_at": iso_z(now)}` with `attribute_not_exists(tk)`. If that condition fails, it **deletes the token item it just wrote** and returns `None`. On success it returns the plaintext key. The claim item can never collide with a token, because token keys are 64-character hex.
  - `class ClaimResult(enum.Enum)`: `ISSUED`, `ALREADY_CLAIMED`, `NOT_ELIGIBLE`, `UNAVAILABLE`.
  - `class ClaimService(client: StripeClient, tokens: TokenStore, product_id: str)`, with `claim(session_id: str, now: datetime) -> tuple[ClaimResult, str | None]`. The key is set only for `ISSUED`. A session that is not found, or fails `claimable_subscription`, is `NOT_ELIGIBLE`. `BillingError` or `Throttled` is `UNAVAILABLE`.
  - `SESSION_ID_RE = re.compile(r"^cs_(test|live)_[A-Za-z0-9]{10,200}$")` in `billing.py`.
  - `lib/pages.py`: `claim_issued(key: str) -> str`, `claim_already(contact: str) -> str`, `claim_not_eligible(contact: str) -> str`, `claim_unavailable() -> str`. Each returns a complete HTML document. Every value is passed through `html.escape`. The issued page shows the key in a `<code>` block with "Copy it now. It will not be shown again", plus one `curl -H "Authorization: Bearer …" https://api.cc2asn.com/2024-01-01/ALL/NO` example.
  - `Deps.claims: ClaimService | None = None` and `Deps.claim_limiter: RateLimiter`, defaulting to `RateLimiter(per_minute=5, per_day=50)`.

Status codes:

| Case | Status |
|---|---|
| Per-IP limit | 429 |
| Bad or missing `session_id` | 400, and Stripe is never called |
| Billing disabled (`claims is None`) | 503 |
| `ISSUED` | 200 |
| `ALREADY_CLAIMED` | 409 |
| `NOT_ELIGIBLE` | 400 |
| `UNAVAILABLE` | 503 with `Retry-After: 30` |

Every response carries `Cache-Control: no-store`, `Referrer-Policy: no-referrer` and `Content-Type: text/html; charset=utf-8`. The per-IP limit uses `_client_ip()`. Log one line per claim outcome to the operational logger (`claim issued sub=… tok=<8-char prefix>` / `claim already` / `claim not-eligible` / `claim unavailable`). Never log the plaintext key.
