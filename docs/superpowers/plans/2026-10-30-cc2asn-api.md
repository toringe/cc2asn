# cc2asn Web API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve the per-country data in `cc2asn-db` over HTTPS with whois-server semantics — free anonymous latest-day lookups, token-gated exact-date historic lookups — at zero-to-near-zero monthly cost.

**Architecture:** Python 3.14 Event Function on Lambda, `aws-lambda-web-adapter` layer with a Function URL front door. The app is a stdlib `http.server` (one request per environment anyway), boto3 for S3 reads (in-memory `latest/` cache) and DynamoDB (provisioned-mode token store + precise per-token quota). In-memory per-IP token bucket for anonymous traffic.

**Tech Stack:** Python 3.14 stdlib + boto3 1.43.x; unittest; uv venv (repo-shared `.venv/`); Makefile zip build mirroring `lambda/` conventions.

**Spec:** `docs/2026-10-29-cc2asn-api-design.md` (read it first — decisions table, API surface, cost model, open items).

## Global Constraints

- Python 3.14; dependencies: **boto3 only** (no web frameworks, no pytest — stdlib `unittest`).
- No emojis in code, comments, or output (aws-sdk-python-usage skill).
- **No hardcoded AWS config** — all via env vars: `PORT` (8080), `CC2ASN_DB_BUCKET` (`cc2asn-db`), `CC2ASN_TOKENS_TABLE` (`cc2asn-tokens`), `RATE_PER_MINUTE` (30), `RATE_PER_DAY` (300), `CACHE_TTL` (300 s). boto3 resolves region from the provider chain (Lambda injects `AWS_REGION`).
- DynamoDB table must be **provisioned mode ≤ 25 RCU/WCU** (always-free tier); never on-demand.
- S3 keys (pinned by the curator's output format): latest `latest/{CC}_{TYPE}`; historic `{YYYY}/{MM:02d}/{DD:02d}/{CC}_{TYPE}`.
- **AWS-side actions (create/modify anything in the account, run any `aws` command) require explicit user approval before execution.** Local file edits, builds, and offline tests are freely allowed.
- Repo state note: uncommitted upstream work exists (`lambda/` runtime upgrade, AGENTS.md, docs/) — do not bundle it into task commits; commit only files the task creates/edits.

## Review Focus

Failure modes the spec implies but no single unit test obviously covers — each is pinned by a named test in its owning task:

1. **Queries must be case-insensitive** (whois uppercases input; `/no` must equal `/NO`) — pinned by `test_path_accepts_lowercase_cc_and_type` (Task 2) and `test_lowercase_country_code` (Task 6).
2. **Malformed dates must 404, never crash** (`2026-13-01`, `2026-02-30`, `19-01-01`) — pinned by `test_invalid_dates_rejected` (Task 2) and `test_malformed_date_returns_404` (Task 6).
3. **Exact-date-or-404, no nearest fallback** (spec decision) — pinned by `test_historic_uses_exact_date_key` (Task 3) and `test_missing_date_returns_404` (Task 6).
4. **Auth header variants** (`Bearer` wrong case/missing/malformed/expired token → 401; valid-but-exhausted → 429) — pinned by `test_authorization_variants` (Task 6).
5. **Rate windows reset** (minute window expiry, day counter reset on date change) — pinned by `test_minute_window_expires` and `test_day_counter_resets` (Task 5).
